# Main Agent Description

이 agents는 최상위 description으로, 다른 agents를 참고하기 전에 반드시 지켜야하는 공통 Rule이다.

## 코드 베이스 작성 규칙

1. 누구나 쉽게 알아볼 수 있도록 최대한 단순하고 직관적으로 작성하도록 한다. 복잡한 알고리즘이나 무거운 모듈은 성능에 큰 차이가 없다면 피한다. 그러나 성능에 큰 차이가 있다면 적극 차용하도록 한다.

2. YAGNI 원칙, 즉 지금 당장 필요한, 요구된 기능만 작성하도록 한다.

3. SOLID 원칙을 지켜서 작성한다.

4. 코드 간의 의존성을 최소화한다. 최대한 디렉터리 내에서 코드의 기능을 구현하도록 한다.

5. 각 코드 파일 최상단에는 주석으로 무엇을 하는 코드인지 자세히 설명을 적는다. 또한 각 메소드 및 변수마다 주석을 간단하게 달아둔다.

## 마일스톤 가이드

각 마일스톤마다 깃 브랜치를 만들어서 진행한다.

다음 단계로 넘어갈 때는 이전 단계의 브랜치를 clone하여 시작한다.

1. 간단한 MVP 개발[브랜치명: milestone/MVP]

기상청 API를 받아와서 정보를 띄우는 간단한 웹 프론트엔드만 작성

2. 시스템 구체화[브랜치명: milestone/web]

기상청 API를 통해서 실시간으로 각 지역의 날씨를 수집하는 백엔드 server를 개발.

이를 PostgreSQL에 저장. 이 단계에서는 스키마만 정의한다.

웹 프론트엔드는 백엔드 서버에서 GraphQL을 사용하여 정보를 한꺼번에 요청하여 받아옴.

3. 프론트엔드 확장[브랜치명: milestone/mobile]

android, iOS 환경에서 사용가능한 프론트엔드 앱을 작성한다.

Android는 Dart로 iOS는 Swift로 작성하도록 한다.
